===================================================
ServerSage - AI-Powered Discord Verification Bot
Functional Specifications v2.0
===================================================

1. Overview and Purpose
-----------------------
ServerSage is an intelligent Discord bot that automates user verification through conversational AI. It leverages Large Language Models (LLMs) to engage users in natural language conversations, classify their skills and experience, detect suspicious accounts, and manage role assignments with persistent database tracking.

2. Core AI/LLM Capabilities
----------------------------

    2.1. Multi-Provider LLM Support
        - Direct integration with OpenAI GPT-4/GPT-3.5-turbo
        - Direct integration with Google Gemini (gemini-1.5-pro, gemini-1.5-flash)
        - Pluggable provider architecture via BaseLLMProvider abstract class
        - Provider-agnostic function calling (tool use) support
        - Automatic response format conversion between providers
        - Custom base URL support for OpenAI-compatible APIs (Azure OpenAI, local LLMs)

    2.2. Function Calling / Tool Use
        - JSON Schema-based function definitions for structured LLM responses
        - propose_user_roles: Structured role classification with confirmation flow
        - categorize_server_roles: Automated role taxonomy generation
        - classify_user: Suspicious account detection with reason extraction
        - Automatic fallback handling when function calls fail

    2.3. Intelligent Role Classification
        - Natural language understanding of user skills, experience, and tools
        - Multi-category classification: Programming Languages, Experience Level, OS, Tools, Frameworks
        - Fuzzy matching of user-mentioned skills to available Discord roles
        - Detection and reporting of unmapped skills (skills without corresponding roles)
        - Conversation context preservation for multi-turn classification

    2.4. Dynamic Server Role Categorization
        - LLM-based automatic categorization of Discord server roles
        - Role hierarchy awareness with configurable boundary filtering
        - Persistent caching of categorized roles (JSON file storage)
        - On-demand and startup-triggered recategorization

    2.5. Suspicious Account Detection
        - LLM-based analysis of user message patterns for threat detection
        - Classification tags: spam, phishing, scam, bot, automated, gibberish, harassment
        - Automatic suspicious role assignment with admin notification
        - Configurable retention period with automatic role removal
        - Periodic cleanup background task

    2.6. Natural Language Generation
        - LLM-generated welcome messages for new members
        - Dynamic conversation responses during verification
        - Localized message generation (multi-language support)
        - New user summary generation for admin review
        - Temperature and token limit configurability

3. Internationalization (i18n)
------------------------------
    - User locale detection from Discord interaction metadata
    - Persistent locale preference storage in database
    - Locale-aware prompt templates with language-specific responses
    - Flag emoji mapping for locale visualization
    - Fallback language handling (English/Spanish defaults)

4. Verification Process Flow
-----------------------------

    4.1. Initiation Triggers
        - Automatic: New member joins server
        - Admin command: /admin verify-user @member
        - Batch processing: /admin initiate-verification-batch count:N
        - Self-service: /assign-roles command

    4.2. DM Conversation Flow
        - Initial greeting with locale-appropriate message
        - LLM-driven multi-turn conversation
        - Role proposal with confirmation buttons
        - Retry mechanism with configurable attempt limits
        - Final attempt best-effort classification

    4.3. Role Assignment Outcomes
        - Verified status: User assigned verified role + skill roles
        - Unverified status: User retains unverified role
        - Partial assignment: Some roles assigned if others fail
        - Unmapped skill notification: Admins notified of missing roles

    4.4. State Tracking
        - In-memory active verification tracking (per user ID)
        - "verification-in-progress" role during active sessions
        - Database-backed role assignment history
        - Conversation history for LLM context

5. Database Architecture
-------------------------

    5.1. PostgreSQL with SQLAlchemy Async
        - Async database operations via asyncpg
        - ORM-based models with proper foreign key relationships
        - Index optimization for common query patterns

    5.2. Tables
        - roles: Discord role metadata (id, name, category, timestamps)
        - assigned_roles: Current user-role assignments with assignment source
        - role_history: Historical record of all role changes
        - unmapped_skills: Skills mentioned but not available as roles
        - user_preferences: Per-user settings including locale preference

    5.3. Role Synchronization System
        - Real-time event sync via Discord events (role create/update/delete)
        - Periodic background sync (configurable interval, default 30 minutes)
        - Manual admin sync via /admin sync-roles command
        - Foreign key constraint enforcement for data integrity

6. Commands and Access Control
-------------------------------

    6.1. Admin Commands (requires configured admin role)
        - /admin verify-user @member: Manual verification trigger
        - /admin initiate-verification-batch count:N: Bulk verification
        - /admin reset-stale-verifications: Cleanup in-progress/unprofiled users
        - /admin rebuild-role-categories: Force LLM recategorization
        - /admin sync-roles: Manual database synchronization

    6.2. User Commands
        - /assign-roles: Self-service verification or role update
        - Interactive role selector for verified users (ephemeral UI)

    6.3. Access Control
        - Role-based admin access via ADMIN_ROLE_IDS configuration
        - Check function validates user roles before command execution

7. Event-Driven Automation
---------------------------
    - on_member_join: Automatic verification initiation + welcome message
    - on_guild_role_create/update/delete: Real-time role sync
    - on_member_update: Track role assignment changes
    - Periodic tasks: Role sync, suspicious role cleanup

8. Prompt Engineering
----------------------
    - External prompt templates in prompts/ directory
    - Python Template substitution for dynamic content
    - Category-specific prompts:
        * role_categorization/system.txt: Role taxonomy prompt
        * user_verification/system_template.txt: Verification conversation
        * welcome_message/system_template.txt: Welcome embed generation
        * new_user_summary/system_template.txt: User summary for admins
        * suspicious_analysis/system_template.txt: Threat detection

9. Configuration System
------------------------
    - Pydantic Settings with .env file support
    - Secret file loading via *_FILE environment variables
    - Type validation with Pydantic types (PositiveInt, HttpUrl)
    - Model validation with @model_validator
    - Runtime configuration access via settings singleton

10. Notification System
------------------------
    - Unmapped skills notifications to admin channel
    - Role assignment failure alerts with debugging info
    - Suspicious account detection alerts with evidence
    - Role sync completion notifications
    - Embed-formatted messages for Discord rich display

11. Error Handling and Resilience
----------------------------------
    - Partial role assignment on individual failures
    - Retry logic for LLM API requests
    - Graceful degradation when LLM unavailable
    - Comprehensive logging with role names (not just IDs)
    - HTTP timeout configuration for slow LLM providers

12. Deployment Options
-----------------------
    - Local Python execution with virtual environment
    - Docker and Docker Compose support
    - Secret management via mounted files
    - Database migrations support
    - Configurable logging levels

13. Metrics and Observability
------------------------------
    - LLM call tracking (count, estimated tokens, chars sent)
    - Response truncation detection
    - Request duration tracking
    - Comprehensive logging throughout codebase
